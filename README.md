## 为什么需要 Ramaria

通用 AI 有一个绕不开的限制：**上下文窗口有限，每次对话都从零开始**。你上周说过的偏好、三个月前提过的经历、去年聊过的重要决定——下一次打开窗口，它往往已经不记得了。即便部分产品提供“长期记忆”，也大多是黑盒、存在云端、对你不透明。

Ramaria 给出另一种答案：**一个完全运行在你本机的长期记忆层**。

- **数据完全属于你**：所有对话与记忆存在本机 SQLite，选用本地模型时可完全离线运行，不经过任何服务器，零遥测。
- **越用越懂你**：随对话持续积累你的经历、习惯与思考方式，归纳成可追溯的人格画像，回应越来越贴合你本人。
- **记忆看得见、追得回**：每一条结论都能回溯到原始对话；记忆可查看、可修正、可删除。

> **适用边界**：Ramaria 面向希望长期使用、并期待 AI 持续了解自己的用户；若只需偶尔查询信息，通用网页版 AI 已经足够。

## 3.0 新面貌

3.0 是一次**后端收口 + 前端完全重写**的版本。它不扩张功能面，而是把 2.x 积累的能力收成一件可以直接使用的产品。

<img src="docs/images/getting-started/03-chat.png" alt="Ramaria 对话界面" width="720">

- **启动不再卡死**：向量索引落库持久化（`memory_vectors`），启动只加载、缺失后台补算，**首条消息立即可发**，构建进度在界面可见。
- **界面整体重写**：常驻珊瑚圆键导航取代侧边栏，**9 个视图**（对话 / 记忆 / 人格 / 规则 / 导入 / 设置 / 调试 + 首次配置与错误页），浅深双主题，设置页两级菜单。
- **三条接入路径**：本地对话、MCP 接入（CodeBuddy / Trae 等）、QQ / Telegram 社交接入；三条路径共用同一份本地数据，各有一份可照着走通的文档。
- **数据单基线**：新库 `data/ramaria.db`（29 张表），记忆与文档向量同库存放；2.x 的 `assistant.db` 不读取、不删除。
- **工程收口**：单份测试基建 `ramaria-testkit`、单份 `MockStorage`、迁移驱动的测试库；契约面与结构自检进入 CI。

> **3.0 是破坏性版本**：数据库不通用、桌面端前端整体重写、旧 `assistant.db` 不迁移。要保留旧内容请在 2.x 上自行导出。

| **接入外部对话前端（MCP）** | 通过 MCP 协议把记忆与人格接入 CodeBuddy、Trae 等支持本地工具的客户端；外部对话可回流到桌面查看并参与记忆加工 |

## 三条接入路径

| 路径 | 你在哪里说话 | 需要准备 | 适合 |
|---|---|---|---|
| **本地对话** | 应用内的「对话」页 | 安装 Ramaria；LM Studio 本地模型或 DeepSeek / OpenAI API Key | 第一次使用；不想配置外部服务 |
| **MCP 接入** | 支持 MCP 的对话客户端（CodeBuddy / Trae / Claude Desktop 等） | 桌面端开启 MCP 开关；另行准备 `ramaria` CLI 并加入 PATH | 已有常用客户端，想让它带上你的记忆 |
| **社交接入** | QQ / Telegram | NapCat 等 OneBot v11 协议端，或 Telegram bot token | 想在聊天软件里直接对话 |

- 三条路径共用同一份本地数据；从任何入口说的话，记忆都汇到同一处。
- 安装包**不随带** `ramaria` 命令行，MCP 路径需要另行获取 CLI；没有 CLI 时客户端拉不起 MCP 服务。
- 社交通道默认关闭，且外部会话默认不放行；开启与放行都在桌面设置里完成。

更细的前置条件、步骤与验证见 [新手引导](docs/getting-started.md)。

## 记忆如何形成

Ramaria 的记忆不是“把聊天记录塞进 Prompt”，而是一套自下而上、可追溯、会遗忘的系统。

### 四层记忆

```
④ 人格画像   →  对你的整体印象：表达风格、行为模式、核心观念
       ↑ 从事件中持续归纳，并随时间校准（Phase A/B/C 三级置信度）
③ 重要事件   →  从多段对话中提炼出的离散事件，如工作变动、重要关系变化
       ↑ 积累到一定程度后自动提炼
② 对话小结   →  每段对话结束后自动生成的摘要、关键词与情绪记录
       ↑ 对话结束时自动整理
① 原始聊天   →  每一条原始消息，永久保留
```

层与层之间通过数据库外键双向关联——任何一条上层结论都能下钻回原始对话，这是黑盒记忆做不到的。

- **L0 原始消息**：永久保留，不过滤，标记发言人。
- **L1 对话小结**：会话结束时生成（手动保存或空闲 10 分钟自动结束）；含摘要、关键词、时段、氛围、情境强度与**发生时间**（来源 = 会话内最早消息）。
- **L2 重要事件**：未吸收 L1 ≥ 5 条或最早未吸收超过 7 天时提取；LLM 不可用时回退规则式降级；被吸收的 L1 以较低权重保留，支持溯源与回滚。
- **L3 人格画像**：Phase A 统计推断 + Phase B LLM 推断 + Phase C 增量更新；画像分 private / trusted / public 共享级别，控制注入范围。

### 混合检索与遗忘

```
用户消息 + 当前人格
  → Persona-Aware 过滤（按共享级别过滤记忆）
  → 四通道并行：
      ① 向量通道（语义相似度）
      ② BM25 通道（自研全文索引，词典增强分词）
      ③ 图谱通道（实体关系关联召回）
      ④ 关键词镜像通道（词池倒排 + 别名归一，可关）
  → Token 预算（超窗口在句子边界截断）
  → RRF 倒数排名融合（缺通道不惩罚）
  → Ebbinghaus 遗忘曲线衰减（按事情发生时间；salience 越高衰减越慢）
  → Top-K 注入 System Prompt
```

**关键词会收敛，不会发散**：每次 L1 生成时把历史词条作为候选喂给模型，引导优先复用已有词条，避免同义词越积越多、检索精度持续下降。

**记忆会遗忘**：不是所有内容都同等重要。显著性的高低决定衰减速度——重大人生事件保留更久，琐碎事务更快淡化。三年前的对话就是三年前的记忆，不会因为最近导入而“永远新鲜”。

### 与通用方案的差异

| 维度 | 通用 AI（ChatGPT 等） | 微调 / LangMem | **Ramaria** |
|---|---|---|---|
| 学习内容 | 无跨会话记忆 | 语气、风格、措辞 | 经历、习惯、情感纹理、思维方式 |
| 记忆方式 | 上下文窗口（有限） | 固化在权重 / Prompt 注入 | 结构化存储 + 动态检索 + 遗忘曲线 |
| 可解释性 | 黑盒 | 黑盒 | 树状关联 L0→L3，可回溯原始对话 |
| 更新机制 | 无 | 重新训练 / 手动更新 | 实时写入，全自动管线 |
| 隐私 | 数据上云 | 数据上传训练方 | **全量本地**，LM Studio 模式完全离线 |
| 人格推断 | 无 | 固定 Prompt | 自动推断，Phase A/B/C 三级置信度 |
| 检索精度 | 单窗口 | 向量 / 关键词单通道 | 四通道 RRF 融合 + Persona-Aware |

## 下载与安装

### 系统要求

- **Windows 10（1809 及以上）/ Windows 11**（目前仅支持 Windows；macOS / Linux 已列入路线图）
- 建议 8 GB 以上内存
- 界面依赖系统 WebView2 运行时；安装包内嵌在线引导程序，系统缺失时在安装期联网获取
- 需要自备 LLM 后端：LM Studio（免费本地）或 DeepSeek / OpenAI API Key
- 如需向量检索，自备本地嵌入模型文件；不配置时向量通道降级，关键词与图谱通道仍可用

### 两个安装包

| 平台 | 文件 | 大小 | SHA-256 |
|------|------|------|---------|
| **Windows x64（CPU，推荐）** | `Ramaria_3.0.0_x64-setup.exe` | 13.5 MB（14,110,176 字节） | `E9DC4BD4BCD9E004BE486ACB33FC091B99FE424CF643049A7ADB6F2BDCD0444C` |
| Windows x64（CUDA） | `Ramaria_3.0.0_x64-cuda-setup.exe` | 13.9 MB（14,621,281 字节） | `5B9BEE9589FD4B6F57DCCF351605B30F8898AAC119518E023E3A511F540DEC28` |

- 下载页把 CPU 包放在首位；不确定选哪个时，先用 CPU 包。
- CUDA 包面向有 NVIDIA 显卡且安装了系统 CUDA 运行时的机器；缺少驱动或运行时时嵌入自动回退 CPU，不会崩溃。
- 两个包共用同一安装身份与数据目录，**只能装一个**；先后安装即覆盖升级，不迁移数据。
- 安装包未进行代码签名（与此前各版本一致），Windows 可能显示“未知发布者”；请以上表 SHA-256 校验文件完整性。

### 第一步：安装

双击安装包，按中文向导完成安装。默认安装到当前用户目录，无需管理员权限。

### 第二步：选择模型后端

| 后端 | 费用 | 网络要求 | 适合 |
|------|------|---------|------|
| **LM Studio** | 免费，依托本机算力 | 可完全离线 | 注重隐私、愿意花少量时间下载模型，**推荐新用户** |
| **DeepSeek** | 云端 API，按用量计费、成本较低 | 需要联网 | 希望省心、追求性价比 |
| **OpenAI** | 云端 API，按用量计费 | 需要联网 | 已在使用 OpenAI、需要全面能力 |

首次启动进入三步配置向导：

1. **对话模型**：选本地或线上，填地址 / 模型名称 / API Key，点「测试连接」。
2. **嵌入模型**：选择本地模型文件夹（需含 `config.json`、`tokenizer.json` 与权重文件），点「校验模型路径」；也可以跳过，跳过只影响语义检索，不影响对话。
3. **确认并进入**：核对摘要后保存，直接进入对话页，不等待索引构建。

> 3.0 没有应用内嵌入模型下载入口，请自备模型文件（默认 `bge-small-zh-v1.5` 约 100 MB；可选 `Qwen3-Embedding-0.6B` 约 1.2 GB）。模型下载命令已具备，但界面入口留待后续版本。

首次使用线上 API 时会弹出隐私确认，勾选「我已知晓上述数据范围与去向」并确认后才会发送至云端；LM Studio 本地模式下不会出现该提示。CLI 首次调用线上服务时另有交互确认。

### 第三步：开始对话

配置完成后自动进入对话界面。建议在结束一段对话时点击右上角「保存对话」（或闲置 10 分钟后自动保存），系统将据此整理并沉淀记忆。

## 常见问题

<details>
<summary><b>展开查看常见问题</b></summary>

**Q：软件是否收费？**
Ramaria 本身免费开源（MIT 协议）。费用仅来自所选的模型后端：LM Studio 使用本机算力，不产生费用；DeepSeek / OpenAI 按调用量计费。

**Q：是否必须联网？**
不必。使用 LM Studio 并加载本地模型后可完全离线运行，对话与记忆均留在本机。

**Q：与 ChatGPT、豆包等通用 AI 有何区别？**
通用 AI 以单次问答为主，不保留跨会话的个人记忆；Ramaria 会将使用者的经历、偏好与表达方式持续沉淀为本地记忆，在后续对话中自动调用，且这些记忆对使用者可见、可修改、可删除。

**Q：如何让 CodeBuddy、Trae 等工具用上 Ramaria 的记忆？**
在桌面「设置 → 社交与接入 → MCP」打开总开关，复制面板给出的配置片段（含 `--db` 库路径），粘贴到对应客户端的 MCP 配置中并重连。默认关闭，随时可关。注意：安装包不随带 `ramaria` 命令行，MCP 路径需另行准备 CLI 并加入 PATH。

**Q：如何导入 QQ 聊天记录？**
先通过 QQChatExporter（v6.x）将记录导出为 JSON，再在「导入」页经四步向导完成（选择 → 预览 → 执行 → 完成）。快速导入保留记录并生成摘要；深度导入会进一步提取事件与画像。导入内容与本地对话同等对待，全部存储在本机。中途关闭或图片未处理完，可在导入页点「继续处理」补齐。

**Q：导入的旧聊天记录，记忆会不会“永远新鲜”？**
不会。记忆的衰减与排序按「事情实际发生的时间」计算——三年前的一段对话就是三年前的记忆，随时间自然淡化；跨批次导入的浏览顺序也按真实时间排列。

**Q：软件会记住哪些内容，是否可以查看？**
可以随时查看。「记忆」页包含对话小结、重要事件、性格画像与知识卡片四个标签，任一结论都可以追溯到对应的原始对话。

**Q：对话内容是否安全？**
数据默认存储于本机数据库（`%APPDATA%\Ramaria\data\ramaria.db`）。本地模型模式下，对话与记忆加工不发起网络请求；云端模式下，对话内容与召回到的记忆才会发送至所选服务商。检查更新、社交接入等联网功能需主动点击或开启。软件不包含统计上报或遥测。

**Q：API Key 是否会泄露？**
不会。API Key 交由 Windows 凭据管理器保管，不写入配置文件或日志；导出诊断信息时也会自动脱敏。

**Q：如果软件判断错误怎么办？**
性格判断均带有置信度，样本不足时会标注「数据不足」而非强行下结论；行为规则可随时编辑或禁用，每条判断都附有证据链。3.0 的人格画像不提供逐条特质编辑，可修正名称、描述与头像，或重载画像。

**Q：对话支持 Markdown 或直接发图片给模型吗？**
3.0 的对话正文按纯文本渲染，Markdown 语法按原文显示；本地发图会存入会话，开启图片理解时后台生成描述，但 3.0 还不支持把当轮图片直接作为对话模型输入。

**Q：如何彻底删除数据？**
设置页可导出会话与消息（JSON / Markdown；CLI 按人格导出时可附 L1 摘要），也可直接删除 `%APPDATA%\Ramaria\data\ramaria.db` 后重新开始。要保留完整记忆与向量，请先备份整个数据目录。2.x 的 `assistant.db` 不会被 3.0 读取，可自行删除。

**Q：是否支持 macOS 或移动端？**
目前仅提供 Windows 安装包；macOS / Linux 已列入路线图，移动端暂无计划。

## 隐私与数据安全

- **本地模型（LM Studio）**：数据不出本机，支持完全离线。
- **云端 API（DeepSeek / OpenAI）**：当前对话、System Prompt 与召回的记忆会发送至所选服务商；3.0 起本地记忆恒随对话注入，不再提供关闭开关。首次使用需按「服务商 + 服务地址」完成隐私确认。
- **图片理解**：开启「模型支持图片理解」且使用线上模型时，导入、社交与本地发图的图片会随理解请求外发；本地模型模式下只发往本机。
- **API Key**：由 Windows 凭据管理器保管，不落明文。
- **日志策略**：不记录完整对话原文，敏感信息自动截断或脱敏。
- **零遥测**：不收集使用统计，不向开发者回传任何数据；「检查更新」仅在手动点击时访问 GitHub Releases API。
- **数据导出范围**：JSON / Markdown 导出的是会话与消息（可选附 L1 摘要），不是全库备份；完整的记忆、画像与向量需备份 `ramaria.db`。

完整说明见 [隐私说明](docs/privacy-notice.md)。

## 版本历史

### v3.0.0 — 2026-10-27（发行 3.0.0）

**「整合收口」**：把 2.x 堆起来的能力收成能直接用的产品。

- **宿主接线**：托盘未读徽标、系统通知与通知点击定位、当前会话到达即已读、关闭确认。
