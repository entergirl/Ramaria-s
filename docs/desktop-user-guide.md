# Ramaria 桌面使用指南

> 版本：2.7  
> 适用平台：Windows

## 概述

Ramaria 桌面应用是一个本地运行的个人 AI 陪伴记忆系统。具备以下核心能力：

- 💬 **智能对话**：连接 LM Studio 本地模型或 DeepSeek/OpenAI 云端 API
- 🗣️ **主动对话**：无需输入也会主动开口（选题 + 判据 + 打扰控制 + 人格级开关，可一键关闭）
- 🔴 **未读标记**：会话列表未读计数、打开即已读、托盘未读数字徽标
- 🧠 **分层记忆**：自动从对话中提取摘要（L1）、事件（L2）、性格画像（L3）
- 🎭 **人格画像**：自动推断人格特征，LLM 以该人格身份对话
- 🔍 **混合检索**：向量 + BM25 + 知识图谱 + 关键词镜像多通道融合（RRF 倒数排名融合）
- 📥 **QQ 聊天导入**：导入历史 QQ 聊天记录，快速或深度模式
- 🔗 **社交平台接入（v2.7）**：接入 QQ（NapCat / OneBot v11）与 Telegram bot，双向收发消息并参与记忆管线（默认关闭）
- 👥 **人格管理**：查看、编辑人格信息，设置默认对话人格
- 📊 **诊断导出**：一键打包日志/配置/系统信息用于故障排查
- 🔌 **MCP 接入**：把记忆与人格接入外部对话前端（CodeBuddy / Trae / DeepSeek Harness 等）

## 安装

### 系统要求

| 项目 | 要求 |
|------|------|
| 操作系统 | Windows 11 / Windows 10 1809 及以上（64 位） |
| 内存 | 8 GB+ 推荐 |
| 磁盘 | 安装包约 8.9 MB，安装后程序本体约数十 MB；本地嵌入模型首次运行时另行下载（默认 bge-small-zh-v1.5 约 100 MB，可选 Qwen3-Embedding-0.6B 约 1.2 GB），LM Studio 对话模型需在 LM Studio 中单独下载 |
| 运行环境 | 无需额外运行时 |

### 安装步骤

1. 下载 `Ramaria_2.5.0_x64-setup.exe` 安装程序
2. 双击运行安装程序（中文引导）
3. 选择安装路径（默认 `%LOCALAPPDATA%\Ramaria\`）
4. 完成安装，桌面出现快捷方式

**注意**：安装包不含 LLM 模型，模型需单独下载（LM Studio 内下载或使用云端 API）。

## 首次配置

首次启动时进入全屏配置向导，完成后自动进入对话界面。

### 步骤 1：选择 LLM 后端

| Provider | 类型 | 说明 |
|----------|------|------|
| **LM Studio** | 本地 | 免费，需自行下载模型，数据不出本地 |
| **DeepSeek** | 云端 | 需 API Key，性价比高 |
| **OpenAI** | 云端 | 需 API Key，功能全面 |

### 步骤 2：配置连接

- **LM Studio**：确保 LM Studio 已启动并加载模型，默认地址 `http://localhost:1234/v1`
- **DeepSeek / OpenAI**：输入 API Key（保存到 Windows 凭据管理器，不写入配置文件）

### 步骤 3：确认并完成

系统自动初始化数据库、注册人格文件、验证后端连接。配置完成后进入对话主界面。

## 对话（主界面）

### 发送消息

- 底部输入框输入消息，按 `Enter` 发送，`Shift+Enter` 换行
- 助手回复流式逐字显示，带打字光标
- 流式回复期间输入框禁用，显示"正在生成…"
- **空回复按错误处理（v2.9）**：后端返回空内容时提示可重试，不留空气泡、不写入记录

### 对话体验（v2.9）

- **更像本人**：回复的语气与分条习惯来自人格的说话示例（常驻参考），整体更口语、更少"总结式"腔调
- **分条气泡**：回复中的 `||` 是"分多次说"的分隔符，客户端渲染为多个气泡；回复内不再用换行代替分条
- **DeepSeek 思考模式（默认开）**：回复前会先思考（首字延迟略增），可在「设置 → 后端配置」关闭思考或调整注入位置；结构化记忆处理不受影响
- **撤回提示**：社交平台消息被撤回后，对话中显示「〔对方撤回了一条消息〕」；未读过的消息内容不再进入上下文，已读过的保持上下文连贯
- **预设可编程**：可从预设文件导入人格（见「人格管理 → 导入预设」），导入的画像默认不会被自动推断改写

### 会话管理

- 聊天页眉显示当前对话人格（头像 + 名称 + 状态指示），右侧为「📋 历史」与「💾 保存对话」按钮
- 点击「📋 历史」展开左侧会话抽屉：列出历史会话（活跃 / 已关闭 / 导入标签区分），点击切换会话
- 会话抽屉在存在未读消息时显示未读计数（超过 99 显示 `99+`）；**打开会话即标记已读**（抽屉点击 / 记忆跳转 / 启动恢复 / 通知定位 / 回复完成五处入口）
- 已关闭会话显示关闭时间，只读不可续写
- **保存对话**按钮：关闭当前 session 并触发记忆管线（L1 摘要 → 可能触发 L2/L3），前端不清屏，自动开始新对话

### 已关闭会话（只读）

- 查看已关闭 session 时隐藏输入框，显示"此对话已关闭"提示
- 提供"开始新对话"按钮快速开始新的会话

### 社交平台会话（只读，v2.9）

- QQ / Telegram 会话在桌面客户端**仅可查看**：隐藏输入框，提示"该会话来自社交平台，仅可查看；回复请在对应平台进行"
- 按发言人视角展示：他人消息在左侧、各带昵称；本机侧与机器人的发言在右侧
- 回复请回到 QQ / Telegram 进行（服务层同样拒绝客户端向社交会话写入本地消息，防止绕过）

### 人格选择

- 输入框上方选择当前对话人格（默认 `rama-0001`）
- 不同人格使用不同的 System Prompt 和记忆过滤

### Markdown 支持

助手回复支持 Markdown 渲染：标题、粗体/斜体、代码块、列表、链接。输出经过安全过滤，禁止原始 HTML。

## 主动对话（v2.4 起步 / v2.5 收敛）

Ramaria 可以不依赖你的输入主动发起对话——由选题器从记忆里挑选话题，经调度与打扰控制后投放为系统通知与应用内消息（消息气泡带「主动」标识）。

### 触发与克制

- **人格级开关（v2.5）**：主动消息按人格放行——默认「自动」：与某人格**对话过一次**（你在此应用中真实发言过，导入的历史不计）后自动开启；也可在「设置 → 主动对话 → 主动消息名单」中把某人格手动设为「开启 / 关闭」。从未对话过的人格默认不会打扰你，需要时可手动开启（提示可能缺少话题素材）。
- **系统用户人格不参与**：名单中「用户」人格行禁用（用户人格不承担对话职能）。
- 应用运行期间按检查节拍（默认 5 分钟）判断是否适合开口；满足全部条件才会考虑：距上次对话空闲 ≥4 小时、不在免打扰时段、该人格当日投递未达上限（默认 3 条）、**全部人格合计未达全局日上限（默认不限）**、距上次投递已过冷却（默认 8 小时）、未处于连续未回应退避、已过首次启用宽限期（默认 3 天）。
- 开口前由 AI 判据做一次轻量决策（是否开口 / 聊哪个候选 / 角度与语气）；判据失败或系统不可用时自然保持安静。
- 按你的历史作息软加权：低活跃时段不主动开口（样本不足时不启用）。
- 话题来源：高显著事件 / 未了结的关心 / 时间节点（事件后第 N 天）/ 行为习惯情境；同一事件或规则在冷却窗口内不重复。

### 收到消息后

- **桌面通知**：显示消息预览；点击通知聚焦主窗口并定位到对应会话（安装版随安装器注册通知身份，点击可靠）。
- **应用内**：聊天页出现带「主动」标识的消息（可能新建会话，或在相关事件的会话里续写）；会话列表显示未读计数，打开会话即标记已读。
- 主动消息正常参与记忆回流（摘要 / 事件 / 画像 / 风格），与你的消息同权。

### 关闭与调整

设置 → 主动对话：总开关 / 每日上限 / 最小空闲 / 免打扰时段 / **主动消息名单（逐人格三态开关）**；高级参数（全局日上限、判据开关、活跃时段、效价与阈值、冷却等）在「高级设置」中调整。

## 记忆查看

点击侧边栏 🧠 进入记忆页。按人格筛选，四个 Tab 切换（L1 摘要 / L2 事件 / L3 性格 / 知识）：

### L1 摘要

- Bento Grid 卡片布局，粉色渐变背景
- 每次会话结束后自动生成（手动关闭或空闲 10 分钟自动关闭）
- 显示：摘要文本、氛围、情绪效价、显著性强度条、情境强度
- 时间显示为**发生时间**（v2.8）：导入的历史对话按其真实发生时间展示与排序，与导入先后无关
- 点击卡片展开完整内容

### L2 事件

- 蓝色标记事件列表
- 从多段 L1 中自动提取的离散事件
- 触发条件：未吸收 L1 ≥ 5 条，或最早未吸收 L1 超过 7 天
- 点击展开：事件详情、置信度、态度描述、关联成员

### L3 性格

- 三层标签云：底色（粉色）、主色调（蓝色）、点缀（灰色）
- 自动从事件中推断生成（Phase A 统计 + Phase B LLM + Phase C 增量更新）
- 触发条件：未吸收事件 ≥ 10 条，或最早事件超过 30 天
- 点击标签查看：含义、证据链、置信度评分

### 知识（只读）

- 展示 persona 的结构化知识事实（`field` 类别 / 事实内容 / 置信度 / 来源 / 版本链）
- 来源为事件抽取与仲裁（`auto_fact_detect` 开启时）或手工写入；**只读，双端均不提供事实删除**
- 事实按 `basic_info` / `personal_status` / `interests` / `social` / `history` / `recent_context` / `speaking_style` 分组展示，历史版本沿版本链折叠查看

## 人格管理

点击侧边栏 👥 进入人格页。管理系统中所有已注册的人格。

### 人格列表

- 卡片网格布局，每张卡片显示：
  - 类型图标（👤 用户 / 🌸 助手 / 💬 角色 / 🎭 动画 / 📖 原创 / 📜 历史）
  - 名称
  - 类型标签（user / rama / char 等）
  - 来源（local / qq 等）
  - 描述预览
  - ⭐ 默认标记
- 默认对话人格显示星标标记

### 人格详情

点击人格卡片进入详情页：

- **基本信息编辑**：可在线修改名称、头像 URL、描述，修改后保存到数据库
- **重载按钮**：触发该人格的 L2→L3 性格推断管线（重新计算性格特征）
- **设为默认**：将该人格设为默认对话人格，后续新对话默认使用

### 人格来源

| 来源 | 创建方式 |
|------|---------|
| `local` | 通过 `personas/*.toml` 文件注册（如默认人格「黎杋枫」） |
| `qq` | QQ 聊天记录导入时自动创建 |
| `manual` | 用户通过 CLI `persona reload` 手动注册 |
| `preset` | 预设文件导入（v2.9；见下节） |

### 导入预设（v2.9）

- 入口：人格页列表工具栏或空状态中的「导入预设」按钮
- 支持格式：`persona.toml` 超集（`[persona]` / `[traits]` / `[[facts]]` / `[[examples]]` / `[[behavior_rules]]` / `[prompt]`）、SillyTavern 角色卡（`.json` / `.png`）
- 流程：选择文件 → **预览**（逐条列出将写入的性格 / 事实 / 示例 / 规则，确认后才写库）→ 确认导入 → 结果提示（uid / 模式 / 写入计数 / 拆解状态）
- **导入不会失败**：文件里的自由文本块无法拆解或未确认隐私时，原文保留在人格配置里，人格照常建成
- **Manual 保护**：导入写入的画像默认带"手工"标记，后续自动推断不会覆盖或删除；需要让推断接管时，用 CLI `ramaria persona allow-inference <uid>`
- 路径限制：文件需放在「文档 / 下载 / 桌面 / OneDrive」目录下（与聊天记录导入同一策略）

## 规则管理

点击侧边栏 ⚖️ 进入规则页，管理 persona 自动学习到的行为规则（情境 → 反应）。

- **规则列表**：按 persona 筛选；展示来源（Auto 自动学习 / Manual 手工）、启用状态、情境关键词与规则文本摘要
- **详情**：规则文本（reaction / avoid）、情境关键词、情感强度/主动程度/详细度/正式度参数、置信度/稳定性/证据数
- **启用 / 禁用**：即时生效并持久化（禁用会写 S1 反馈日志）
- **手工编辑**：修改 reaction / avoid（编辑后规则转为 Manual 并写反馈日志，后续自动学习不会覆盖）
- **证据链**：规则 → 事件 → 原文摘要溯源（脱敏展示，不显示原文全文）
- **删除**：破坏性操作，需在弹窗中确认

> 规则页与 CLI `ramaria rule` 同源同能力；**不提供事实删除路径**。

## 调试面板（默认隐藏）

在设置页开启「启用调试（开发者模式）」并重启后，侧边栏出现 🧪 调试页，含三个只读页签：

- **关键词**：keyword_pool 三态分层（规范词 / 别名 / 待确认）与计数；待确认别名可确认或驳回（与 CLI `ramaria keyword` 同一状态机；当前生产侧尚无自动写入待确认别名的路径，该列表可能为空）
- **风格统计**：按 persona 展示五维风格统计、样本量、状态标注（数据不足时显示"数据不足"）与自动生成的风格规则文本
- **评估结果**：选择目录后读取最近一次探针 run / evaluate 产物，展示档位得分、维度聚合、辅助指标与注入闸门语义（只读，不触发后端运行）

## 导入功能

点击侧边栏 📥 进入导入页。支持导入 QQ 聊天记录。

### QQ 聊天记录导入

支持格式：
- **JSON 格式**：QQChatExporter v6.x 导出的 JSON 文件（流式解析大文件；TXT / PCQQ 不在 2.0 范围）

### 三步导入向导

**Step 1 — 选择文件**：
- 点击"浏览"选择一个 QQ 聊天记录文件
- 可选择填写导出者画像名称和对方画像名称（可选，默认自动填充）
- 预览文件基本信息（消息数、时间范围）

**Step 2 — 预览报告**：
- 显示文件格式、消息数量、时间跨度、参与方信息
- 确认后将创建的画像信息

**Step 3 — 选择模式并导入**：

| 模式 | 说明 | 适合场景 |
|------|------|---------|
| **快速导入** | 仅写入 L0 消息，生成 L1 摘要 | 只想保留聊天记录，快速完成 |
| **深度导入** | 写入 L0 消息 → 生成 L1 摘要 → 提取 L2 事件 → 推断 L3 性格 | 希望完整分析聊天内容，提取人格特征 |

- 导入进度在导入页（Step 3）内通过进度条展示
- 快速模式跳过 L2/L3，深度模式走完全管线
- 重复消息自动去重：同一文件内去重 + 跨文件按导入指纹（SHA-256）跳过已导入消息（已实装）
- 含图片的记录：开启「模型支持图片理解」后会对图片生成简短描述（用于记忆摘要与对话展示；本地模型不出本地，关闭时图片以占位符保留）

### 深度处理

快速导入后，可在记忆页点击"深度处理"按钮，手动触发 L2→L3 级联，将已导入的对话进一步分析。

### 继续处理（v2.8）

导入已完成、但仍有图片未理解或摘要缺失时（例如导入中途关闭应用 / 图片理解当时不可用），可在导入页点击**「继续处理」**续跑：

- 自动重扫未理解图片（含按图片指纹从导出目录反查找回资源）→ 补跑缺失的 L1 摘要 → 补触发深度级联；
- 可重复执行：已完成的图片理解与摘要会自动跳过；
- 导出目录会被记住（无需重复选择）；如换了目录位置，可在入口重新选择；
- 图片理解能力关闭期间，附件保持"待处理"状态，能力恢复后即可回补。

## 社交平台接入（v2.7）

把 Ramaria 接入你的 QQ 或 Telegram，让它在这些平台里收发消息并参与记忆管线（消息、图片与记忆归属与本地对话同等对待）。**默认全部关闭**，需在「设置 → 通道」显式开启；连接**随桌面应用启停**（关闭应用即断开）。

### QQ 接入（NapCat + OneBot v11）

Ramaria 通过 **OneBot v11 正向 WebSocket** 连接 QQ 协议端（支持任意 OneBot v11 实现），推荐 [NapCat](https://github.com/NapNeko/NapCatQQ)：

1. 安装并登录 NapCat（跟随其官方文档完成扫码 / 验证）；
2. 打开 NapCat WebUI（默认 `http://127.0.0.1:6099`）→「网络配置」→ 新建 **WebSocket 服务器**：端口填 `3001`（与 Ramaria 默认一致）、消息格式选 `array`，保存并启用；
3. 若该服务设置了 access token，在 Ramaria「设置 → 通道 → QQ」填入同一 token（未设置则留空）；
4. 打开 Ramaria →「设置 → 通道」，开启通道总开关与 QQ，点击「启动」——状态显示「已连接」即就绪；
5. 私聊直接发消息即会得到回复；群聊中只有 **@ 它** 或 **回复它的消息** 才会响应。

> ⚠️ **风控与合规声明**：NapCat 等协议端属**非官方第三方实现**，使用它们登录 QQ 存在账号被限制 / 冻结等风险，请自行评估并遵守腾讯相关协议与当地法律法规；建议使用小号、避免高频发送与批量操作。Ramaria 与 NapCat / NapNeko 无任何隶属关系，不对账号风险负责。

### Telegram 接入（Bot API）

1. 在 Telegram 中与 [@BotFather](https://t.me/BotFather) 对话，发送 `/newbot`，按提示填写名称与用户名，创建完成后得到 **bot token**（形如 `123456789:ABC-DEF...`）；
2. 把 bot token 填入 Ramaria「设置 → 通道 → Telegram」，开启通道总开关与 Telegram，点击「启动」；
3. 在 Telegram 里找到你的 bot，先给它发一条消息（或把它拉进群）；Ramaria 收到首条消息后**自动建立绑定**（显示在「通道 → 绑定」列表）；
4. 群聊中同样只有 @ 或回复才响应；如需它主动说话，在该绑定行打开「允许主动」（还需在「设置 → 主动对话」的名单里放行该人格）。

> 提示：bot token 等价于 bot 的完全控制权，请勿分享；如泄露可在 BotFather 中 `/revoke` 重置。

### 通道面板（设置 → 通道）

| 区域 | 说明 |
|------|------|
| **状态与启停** | 总开关、各平台连接状态（未连接 / 连接中 / 已连接 / 错误）与「启动 / 停止」；配置或凭据改动后需**重新启动通道**才生效（不热重载） |
| **凭据** | QQ access token（可选）与 Telegram bot token；存入 Windows 凭据管理器，不写入配置文件、界面不明文回显 |
| **绑定管理（会话白名单）** | 每个外部会话（私聊 `c2c:...` / 群聊 `group:...`）对应本机侧人格 + 启用开关 + 「允许主动」；收到消息自动建档但**默认不放行（禁用）**——对该会话点击「放行」（启用）后才处理，未放行的消息不入库、不回复（v2.8 白名单语义） |

### 注意事项

- **消息归属**：对方消息归属到其人格（人类成员按平台账号自动派生 `char-` 人格），本机侧发言以绑定人格（默认 `rama-0001`）参与；群聊按发言人各自归属，记忆摘要在封存时按"为谁生成、谁即助手"逐人生成；
- **对话展示（v2.9）**：桌面客户端打开社交会话时按发言人视角展示——他人消息在左侧、各带其昵称，本机侧与机器人的发言在右侧；群聊里模型也能区分"谁在说话"；
- **只读查看（v2.9）**：社交会话在桌面客户端**仅可查看**（输入区隐藏，提示"回复请在对应平台进行"）——回复请在 QQ / Telegram 里进行，避免本地插入的消息无法送达平台；
- **放行制（v2.8）**：新会话自动建档后默认禁用，需显式「放行」才处理消息（白名单）；此前已启用的绑定不受影响；
- **图片（v2.8 起"先理解后回复"）**：收到的图片会下载到本地（≤20MB）并先做一次理解，再生成当轮回复（理解超过 20 秒时按占位符先回复、后台继续补理解）；**下载成功的图片会写入本地图片缓存，桌面客户端会话里可直接看到原图**（v2.9）；使用线上模型且开启图片理解时图片内容会外发（见《隐私说明》）；
- **表情消息（v2.8）**：QQ 表情 / 动画表情与 Telegram 贴纸会折叠为 `[表情]` 参与对话，不再因"无文字"被忽略；
- **回复分条（v2.9）**：社交回复中的分条标记（`||`）会拆分为**多条消息分次发出**（条间约隔 0.8 秒，避免触发平台风控；单条回复最多 5 段，更多内容并入最后一段）；标记本身不会原样发出；
- **撤回（v2.9）**：QQ 侧撤回事件会被识别——对话中显示「〔对方撤回了一条消息〕」；撤回的消息若尚未参与过回复，内容不再进入上下文（如从未发生），已参与过的保持上下文连贯；图片 / 文字均适用；Telegram Bot API 不提供撤回事件；
- **表情与图片发送（v2.9，命令面）**：可给机器人配置表情资产（CLI `ramaria sticker add/list/update/remove`），对话中机器人可按场景用表情回应（未命中时退回纯文字）；本地会话发送图片当前通过 `send_local_image` 命令面提供，界面入口随后续前端改版；
- **主动消息**：默认不在社交平台主动发言——需同时满足「通道总开关 → 该绑定允许主动 → 人格三态」多层开关；平台发送失败不计入投递冷却；
- **数据与删除**：社交消息与本地对话同库同待遇；停用通道不会删除已入库消息，需要时按「数据与隐私 → 本地数据」处理。

## 设置

点击侧边栏 ⚙️ 进入设置页。设置面板采用**目录导航**（v2.8）：左侧目录分「基础 / 高级」两个页签（基础 5 组 12 项 / 高级 6 组 18 项），点击目录项右侧显示对应设置内容；支持深链定位（`#settings/{基础|高级}/{分组}`，如 `#settings/advanced/retrieval`）。

### 后端配置

- 切换 Provider（LM Studio / DeepSeek / OpenAI）
- 修改 Base URL
- 输入/修改 API Key（遮蔽显示，保存到 keychain）
- 图片理解：勾选「模型支持图片理解」（默认关闭；关闭时导入图片整体跳过），勾选后显示「单批理解上限」

### 隐私设置

- 线上记忆注入开关：控制是否将本地记忆注入到云端 API 调用中
- 隐私确认状态：查看/重置各 provider 的隐私确认

### 主动对话（v2.4 起步 / v2.5 收敛）

- **总开关**：关闭后不再主动发起对话（默认开启）。
- **每日上限 / 最小空闲 / 免打扰时段**：基础打扰控制（免打扰支持 `HH:MM-HH:MM`，可跨零点）。
- **主动消息名单（v2.5）**：逐人格显示状态与三态控件（自动 / 开启 / 关闭）——`自动开启（已对话过）` / `未解锁（对话一次后自动开启）` / `已开启（手动）` / `已关闭`；行内切换即时保存；用户人格行显示但禁用。
- **作息与问候（v2.8）**：「作息节律」按你与各人格的活跃时间分布，对主动开口时机做软加权（低活跃时段更克制，样本不足时不启用）；「早安问候」按你的起床时间窗口（默认 ±45 分钟）每日至多推送一次候选；「近期状态」把最近一两周的心情氛围带进对话内容（中性时不添加）。三项均可在「高级设置 → 主动对话」调整或关闭（`rhythm_*` / `greeting_*` / `recent_state_*`）。
- **高级参数**：启用调试后，在「高级设置 → 主动对话」中调整全局日上限（`0` = 不限）、判据开关、活跃时段、效价与阈值、选题冷却与作息 / 问候 / 近期状态等键；保存后即时生效（调度节拍改动需重启）。

### MCP 接入（v2.1）

将 Ramaria 的记忆与人格接入支持 MCP 的外部对话前端（CodeBuddy / Trae / DeepSeek Harness 等）：

- **总开关**：控制 MCP 服务是否可用（默认关闭）；保存后需在客户端重连（重启）MCP 连接才生效。
- **运行状态**：展示配置开关、最近外部活动与活跃外部会话数（stdio 服务由客户端挂载时启动，桌面无法直接观测进程状态）。
- **数据库路径**：展示并一键复制当前库路径。
- **客户端配置片段**：一键复制通用 `mcpServers` JSON 与 DeepSeek Harness 插件 patch 两段配置。
- **人格白名单**：限制外部可见人格（默认全部可见；收紧时需至少保留一项）。
- **原文开关 / 写入开关**：控制原文块是否出端、是否允许外部写入回流。
- **隐私提示**：挂载后被检索到的记忆与外部对话回流内容会随对话发送给该客户端所使用的模型。

### 通道（v2.7）

接入 QQ / Telegram 的开关与绑定管理（连接随应用启停）：

- **总开关与平台开关**：默认全部关闭；打开后点「启动」建立连接，修改配置或凭据后需重新启动通道生效。
- **凭据**：QQ access token 与 Telegram bot token 存 Windows 凭据管理器，界面不明文显示。
- **绑定管理（会话白名单）**：外部会话 → 本机侧人格的映射（收到消息自动建档但默认**不放行**；点击「放行」后才处理该会话的消息；可改绑 / 重新禁用 / 打开「允许主动」）。
- **状态**：未连接 / 连接中 / 已连接 / 错误。

具体接入步骤与风控声明见「社交平台接入」章节。

### 高级设置（需启用调试）

「高级设置」页签默认隐藏：在诊断与更新卡片中勾选「启用调试（开发者模式）」并**重启 Ramaria** 后出现，内含三路检索、知识、风格、注入预算、层间去重、渐进摘要（B3）、画像升级、utt/examples/bridge、日志等 2.0 配置组（每项标注默认值，支持单项/全部恢复默认）。

> 高级项保存经统一写入口同时写入 `config.toml` 与数据库；`log_full_prompt` 为预留项，当前实现未接线（无论开关如何都不会记录完整 Prompt）。

### 诊断与更新

- **当前版本**：显示 Ramaria 版本号
- **检查更新**：查询 GitHub Release 是否有新版本
- **导出诊断信息**：打包日志 + 配置 + 系统信息 → `.zip` 文件（API Key 与敏感字段已脱敏）
- **启用调试**：开发者模式开关（重启生效，见「高级设置」）

### 数据管理

- **导出 JSON**：导出会话与消息为带版本信封的 JSON（与 CLI `ramaria export` 同结构）
- **导出 Markdown**：导出人类可读的对话记录（跳过无消息会话；无可导出数据时不写文件并提示）
- **重建索引**：重建 BM25 和知识图谱索引（含确认弹窗）
- **清理图片缓存（v2.8）**：删除会话浏览用的本地图片缓存（显示文件数与占用空间；不影响原图、导出目录与记忆数据）

## 数据与隐私

### 本地数据

- 数据库：`%APPDATA%\Ramaria\data\assistant.db`
- 日志：`%APPDATA%\Ramaria\logs\ramaria.log`
- 人格文件：`%APPDATA%\Ramaria\personas\*.toml`
- 配置文件：`%APPDATA%\Ramaria\config.toml`
- 图片缓存（v2.8）：`%APPDATA%\Ramaria\data\image_cache\`——会话浏览显示图片时的本地缓存（命名自包含、可随数据目录整体迁移）；可在「设置 → 数据管理 → 清理图片缓存」一键清除（不影响原图与记忆）

### 隐私要点

- **本地模型（LM Studio）**：所有对话和记忆仅存储在本地，不上传任何数据
- **云端 API（DeepSeek/OpenAI）**：对话消息和记忆上下文会发送至对应 API 服务器。首次使用需显式确认隐私，确认记录持久化
- **API Key**：存储在 Windows 凭据管理器，不写入配置文件或日志
- **日志策略**：默认不记录完整用户消息、完整记忆、完整 prompt；用户消息只记录长度等元数据（不落原文）
- **导入数据**：导入的 QQ 聊天记录与本地对话数据同等对待，全部存储在本地 SQLite，不出本地
- **诊断导出**：日志/配置打包时二次脱敏（API Key、敏感字段与个人标识均不外泄）
- **MCP 接入（可选）**：开启后，被检索到的记忆与外部对话回流内容会随对话发送给所挂载客户端所使用的模型；原文块默认不出端，可在面板收紧人格白名单或关闭总开关
- **主动对话（v2.4）**：与对话路径同一隐私门禁——云端后端未完成隐私确认时主动对话静默跳过（不弹窗、不投递）；主动生成所用的记忆上下文只发送给你已配置并确认的后端
- **未读状态（v2.5）**：会话已读水位（最后已读时间）仅存本地数据库，不参与任何网络请求
- **社交平台接入（v2.7，可选，默认关闭）**：收到的消息与图片存入本地库并参与记忆管线；回复生成与图片理解沿用你的后端配置——使用线上模型时相关内容（含被检索的记忆）会随请求发送到该后端；平台侧（QQ / Telegram 服务器）本就持有这些原始消息；凭据存 Windows 凭据管理器；关闭通道即停止连接，已入库数据不自动删除

详见《Ramaria 隐私说明》。

## 故障排除

| 问题 | 解决方案 |
|------|----------|
| LM Studio 连接失败 | 确认 LM Studio 已启动并加载模型，base_url 为 `http://localhost:1234/v1` |
| DeepSeek/OpenAI 401 错误 | API Key 无效或已过期，请在设置中重新输入 |
| 对话无记忆注入 | 检查"线上记忆注入"开关是否开启；确认已有 L1/L2/L3 记忆 |
| 索引异常 | 进入设置 → 重建索引 |
| 数据库损坏 | 删除 `%APPDATA%\Ramaria\data\assistant.db` 后重启，需重新配置和导入 |
| 托盘图标不显示 | Windows 任务栏设置 → 选择哪些图标显示在任务栏上 → 开启 Ramaria |
| 窗口启动慢 | 首次启动需初始化数据库和索引，后续启动应在 1 秒内 |
| 嵌入模型不可用 | 未配置嵌入模型时自动降级为 BM25-only 模式（Degraded 状态），对话功能可用但向量检索不可用 |
| 导入进度停滞 | 大文件导入可能耗时较长，查看导入页进度条；若完全无反应，检查文件格式是否正确 |
| 记忆管线未触发 | session 需手动"保存对话"或空闲 10 分钟后自动关闭才会触发 L1→L2→L3 管线 |
| 窗口隐藏后无法恢复 | 右键系统托盘 Ramaria 图标 → 选择"显示"（含超时保护机制） |
| 需要导出诊断信息 | 设置 → 诊断与更新 → 导出诊断信息 → 选择保存位置 |
| MCP 工具在客户端不可用 | 检查设置 → MCP 接入总开关是否开启；修改配置后需在客户端重连（重启）MCP 连接才生效 |
| 不想收到主动消息 | 设置 → 主动对话 → 关闭总开关；单独屏蔽某人格：在「主动消息名单」将其设为「已关闭」；也可调整免打扰时段 / 每日上限 / 最小空闲 |
| 想收到某人格的主动消息但在名单里是「未解锁」 | 先与该人格对话一次（真实输入一条消息），或直接在名单中手动设为「开启」（提示：可能缺少话题素材） |
| 主动消息太频繁或长期不出现 | 调整「最小空闲小时数 / 每日上限 / 投递冷却」；判据开启时由 AI 决定开口时机，可参考其判断关闭判据回退算法决策 |
| 点击主动消息通知无响应 | 安装版随安装器注册通知身份（AUMID）；若仍无响应，直接在应用内会话列表进入对应会话（通知中心中的历史通知不支持点击定位） |
| 会话列表/托盘未读数不对 | 打开对应会话即标记已读；未读只统计助手回复（你自己的消息与导入历史不计） |
| 通道无法连接（QQ） | 确认 NapCat 已登录、WebSocket 服务器已启用且端口与 Ramaria 一致（默认 3001）、access token 两边一致；改完配置后在「设置 → 通道」重新「启动」 |
| 通道无法连接（Telegram） | 确认 bot token 正确（可在 BotFather 重新复制）、本机可访问 `api.telegram.org`；改完凭据后重新「启动」 |
| 群聊里它不回复 | 群聊只在被 @ 或被回复时响应；确认 bot 在群内、未被管理员限制；QQ 侧确认 NapCat 收到了群消息 |
| 社交消息收不到或发不出 | 查看「设置 → 通道」连接状态与日志；QQ 侧平台风控可能导致发送受限，请降低频率稍后重试 |
| 不想让它回复某个人 / 某个群 | 在「设置 → 通道 → 绑定」中禁用该绑定；或关闭通道总开关 |
