# Ramaria 隐私说明

> 版本：2.5  
> 最后更新：2026-10-06

## 概述

Ramaria 是一个**本地优先**的个人 AI 陪伴记忆系统。本说明解释你的数据在本地和线上的存储与传输方式。

---

## 数据存储位置

所有数据默认存储在本地：

```
%APPDATA%\Ramaria\
├── data\assistant.db          # SQLite 数据库（全部记忆、会话、人格画像）
├── logs\ramaria.log           # 运行日志
├── personas\*.toml            # 人格定义文件
└── config.toml                # 非敏感配置
```

- 数据目录可通过 `RAMARIA_DATA_DIR` 环境变量自定义
- 数据不出本地系统，除非你主动选择使用线上 LLM 后端
- 会话已读水位（未读标记依据）与主动人格开关均为本地数据（数据库 `settings` / `sessions` 表），不参与任何网络请求
- 安装包在系统注册表中登记通知应用标识（`HKCU\Software\Classes\AppUserModelId\com.ramaria.app`，仅写入显示名），卸载时移除

---

## 本地模型（LM Studio）

当你选择 LM Studio 作为后端时：

| 数据类型 | 存储位置 | 是否外传 |
|----------|----------|----------|
| 对话消息 | 本地 SQLite | ❌ 不出本地 |
| 记忆摘要（L1） | 本地 SQLite | ❌ 不出本地 |
| 事件/性格（L2/L3） | 本地 SQLite | ❌ 不出本地 |
| 对话 API 请求 | 发送到 `localhost` | ❌ 只发往本机 LM Studio |
| API Key | 不需要 | — |

**结论**：LM Studio 模式下，你的所有数据完全在本地，不上传任何内容到互联网。

---

## 线上模型（DeepSeek / OpenAI）

当你选择 DeepSeek 或 OpenAI 作为后端时：

| 数据类型 | 存储位置 | 是否外传 |
|----------|----------|----------|
| 对话消息 | 本地 SQLite + API 服务器 | ✅ 发送当前对话 |
| 记忆上下文（L1/L2/L3） | 本地 SQLite + API 服务器 | ⚠️ 取决设置 |
| 系统 Prompt（含人格画像） | 本地 SQLite + API 服务器 | ✅ 发送 |
| API Key | Windows 凭据管理器 | ✅ 随 API 请求发送 |

### 线上记忆注入控制

你可以控制是否将本地记忆注入到线上 API 调用中：

| 设置 | 发送内容 |
|------|----------|
| **开启**（默认） | 当前对话 + 相关记忆（L1/L2/L3）+ 人格画像 → API 服务器 |
| **关闭** | 仅当前对话 → API 服务器 |

此开关在设置页面的"隐私设置"中配置。

## 主动对话（v2.4 起步 / v2.5 收敛）

开启后（桌面默认开启），Ramaria 会在你空闲时主动发起消息（详见《桌面使用指南》「主动对话」章节）。**v2.5 起按人格放行**：仅"对话过一次"的人格自动参与，可在桌面「设置 → 主动对话 → 主动消息名单」逐人格调整：

| 数据类型 | 流向 | 说明 |
|----------|------|------|
| 主动生成请求（人格设定 + 参考记忆上下文 + 选题锚点摘要） | 本地 SQLite +（云端后端时）API 服务器 | 与普通对话同一条生成链路；完全受"线上记忆注入"开关与隐私确认约束 |
| 主动消息本身 | 本地 SQLite | 与你的消息同权参与后续记忆加工（摘要 / 事件 / 画像 / 风格），不额外外传 |
| 选题与判据信号 | 仅本地 | 事件 / 规则摘要与活跃时段信号在本地组装；判据调用只含摘要，不含原文 |

控制项：

- **隐私门禁**：使用云端后端且未完成隐私确认时，主动对话静默跳过（不弹窗、不投递）；本地 LM Studio 不受限。
- **一键关闭**：桌面「设置 → 主动对话」关闭总开关即完全停用；也可逐人格在「主动消息名单」中关闭（开关状态存本地 `settings` 表）。
- **打扰控制**：人格级开关 / 每日上限 / 全局日上限 / 免打扰时段 / 最小空闲 / 投递冷却 / 连续未回应退避 / 首次启用宽限期。
- **仅桌面装配**：命令行与 MCP 接入不会主动发言。
- **只读取数**：`ramaria probe baseline` 仅读取本地已有记录（投递 / 回应计数与配置口径），不联网、不回写。

### API Key 安全

- API Key 存储在 **Windows 凭据管理器**（Credential Manager），不写入配置文件或日志
- Key 通过 HTTPS 加密传输到 API 服务器
- 切换 provider 后可随时在设置中更新 API Key
- Key 在日志和诊断导出文件中不出现（界面/CLI 遮蔽显示为「前 3 字符 + `****` + 后 3 字符」，长度 ≤ 4 时整体 `****`）

## MCP 接入（v2.1）

在桌面「设置 → MCP 接入」开启总开关后，外部 MCP 客户端（CodeBuddy / Trae / DeepSeek Harness 等）可通过 stdio 使用 Ramaria 的记忆与人格：

| 数据类型 | 流向 | 说明 |
|----------|------|------|
| 被检索到的记忆（L1/L2/L3 摘要与画像摘要） | MCP 客户端 → 该客户端所使用的模型 | 随客户端对话发送；`memory_recall` / `chat_send` 均可能包含 |
| 外部对话回流内容 | MCP 客户端 → 本地 SQLite | `chat_ingest` 写入本机数据库，与本地对话同等对待 |
| 原文块（utt） | 默认不出端 | `[mcp].allow_raw_text = false`（默认）时返回中不含原文；开启后才随检索返回 |

控制项（默认保守，可随时在面板调整）：

- **总开关**（`[mcp].enabled`，默认关闭）：关闭时六个工具全部不可用。
- **人格白名单**（`[mcp].allowed_personas`）：限制可见人格范围（默认全部可见）。
- **原文开关**（`[mcp].allow_raw_text`，默认关闭）：控制原文块是否随检索返回。
- **写入与封存开关**（`[mcp].allow_ingest` / `allow_seal`）：控制外部写入与是否允许触发摘要生成。

> 隐私提示：挂载 MCP 后，被检索到的记忆与外部对话回流内容会随对话发送给该客户端所使用的模型；请只挂载你信任的客户端。

## 隐私确认机制

### 首次确认

使用线上 provider 前必须完成显式隐私确认。桌面端在首次配置向导中展示隐私提示，CLI 在首次调用线上服务时进行交互确认，提示内容包含：
- 将发送的数据类型（对话、记忆上下文）
- 数据接收方（API 服务器地址）
- 是否持久化确认

### 持久化选项

| 选项 | 行为 |
|------|------|
| 记住此选择（"下次不再询问"） | 确认记录持久化到数据库，跨重启有效。CLI 交互确认时可选择；桌面配置向导完成时默认持久化，设置页可查看与重新记录确认状态 |
| 不记住 | 仅本次运行有效，重启后再次使用线上服务时需重新确认（仅 CLI 交互流程提供该选择） |

### 变更重确认

以下情况需要重新确认隐私：
- 切换 provider 类型（如从 LM Studio 切换到 DeepSeek）
- 修改 Base URL

切换回本地模型（LM Studio）不会撤销已持久化的线上确认记录。

## 导入数据

### QQ 聊天记录导入

Ramaria 支持导入 QQ 聊天记录：

| 方面 | 说明 |
|------|------|
| **存储位置** | 导入的消息存储在本地 SQLite 数据库，与日常对话数据同等对待 |
| **不上传** | 导入数据不会自动发送到任何服务器 |
| **不匿名化** | 导入数据保留原始消息内容和发送者信息（QQ 号、昵称等），不做匿名化处理 |
| **去重** | 同一文件内的重复消息自动去重；跨文件按导入指纹（SHA-256）跳过已导入消息（已实装） |
| **画像创建** | 导入时为聊天参与者自动创建人格画像（`source="qq"`），可在人格页查看并编辑名称、头像、描述（界面与 CLI 均不提供单独删除人格的操作，见下文「数据删除」） |
| **记忆管线** | 深度导入模式会触发全套记忆管线（L0→L1→L2→L3），提取的记忆与日常对话记忆同等待遇 |

**注意**：如果你使用线上 LLM 后端且在导入后使用对话功能，相关记忆上下文可能随对话 API 请求发送到服务器。建议在使用线上 API 时关闭"线上记忆注入"开关，或使用 LM Studio 本地模式处理导入后的记忆。

## 诊断数据导出

Ramaria 提供诊断信息导出功能（设置页 → 诊断与更新 → 导出诊断信息），用于故障排查。

### 导出内容

| 数据类别 | 内容 | 是否脱敏 |
|----------|------|----------|
| 日志文件 | 最近 1000 行运行日志 | ✅ 消息类字段替换为字符数占位 `<N chars>`；绝对路径只留文件名 |
| 配置文件 | `config.toml` 完整内容 | ✅ API Key 替换为 `[REDACTED]` |
| Schema 信息 | 数据库版本、索引版本 | — |
| 系统信息 | OS 名称、版本、架构 | — |

### 安全保证

- **API Key 不泄露**：配置文件中的 API Key 通过模式匹配检测并替换为 `[REDACTED]`
- **消息内容保护**：导出前对日志与配置做二次脱敏——字段名含 `content`/`message`/`preview`/`summary` 等的值一律替换为 `<字符数>`，不输出原文；绝对路径（可能含 QQ 号/昵称）只保留文件名
- **日志本身已脱敏**：日志按设计只记录长度、计数与错误链，不记录消息原文（详见下文「日志策略」）
- **本地打包**：导出的 `.zip` 文件在本地创建，不自动上传
- **用户掌控**：导出前弹出原生保存对话框，由用户选择保存位置

> ⚠ 诊断 `.zip` 文件可能包含敏感信息（如对话时间戳、关键词标签、人格画像名称等）。请妥善保管该文件，仅发送给可信的开发者进行故障诊断。

## 日志策略

### 默认行为

- 日志文件：`%APPDATA%\Ramaria\logs\ramaria.log`
- **不记录**：完整用户消息、完整记忆内容、完整 Prompt
- **记录的上下文**：tracing span、请求 ID、耗时、错误链

### 用户消息处理

对话中的用户消息**不写入日志原文**——只记录长度等元数据（如 `msg_len=12`），用于排障时判断请求规模；导入路径中的个人标识（QQ 号、昵称、文件路径）同样经遮蔽处理后才进入日志。

### 完整 Prompt 日志

`[logging].log_full_prompt` 为**预留配置项（当前实现未接线）**：无论取值为 `true` 还是 `false`，当前版本都不会记录完整 Prompt。后续版本如启用该能力，将先更新本说明并在界面给出显式隐私警告。

```
⚠ 该开关为预留项：当前版本不记录完整 Prompt，取值不影响隐私行为。
```

### LLM 调用日志

每次 LLM 调用记录：
- `trace_id`：请求追踪 ID
- `provider`：后端类型
- `duration_ms`：调用耗时
- `status`：成功/失败
- 不记录请求体和响应体内容

## 前端安全

Ramaria 桌面应用使用 WebView 渲染界面，采取以下安全措施：

### 内容安全策略（CSP）

```
default-src 'self';
style-src 'self';
script-src 'self';
connect-src 'self' ipc: http://ipc.localhost https://ipc.localhost https://api.deepseek.com https://api.openai.com;
img-src 'self' data:;
font-src 'self'
```

**要点**：
- 禁止内联脚本和内联样式（`'unsafe-inline'` 已移除）
- 禁止加载任何远程脚本（`script-src 'self'`）
- 禁止加载远程图片（`img-src 'self' data:`）
- 字体自托管，不依赖外部 CDN（`font-src 'self'`）
- 网络连接仅允许 Tauri IPC 和配置的 API 端点
- 所有行内脚本已外部化到独立 JS 文件

### Markdown 安全

LLM 回复中的 Markdown 经过白名单过滤：
- 允许：标题、粗体/斜体、代码块、列表、链接
- **禁止**：原始 HTML、`<script>`、事件处理器（`onclick`/`onerror` 等）、`javascript:` / `data:` 协议
- 所有输出在渲染前 sanitize
- 错误消息使用 `textContent` 而非 `innerHTML` 渲染，防止 XSS 注入

### Tauri 权限

桌面应用采用最小权限原则：

| 权限 | 用途 |
|------|------|
| `dialog` | 保存文件对话框（导出、诊断）、打开文件对话框（导入） |
| `notification` | Windows Toast 桌面通知 |
| `store` | 非敏感配置本地存储 |
| `core:window` | 窗口显示/隐藏/关闭 |

**不具备的权限**：网络文件系统访问、剪贴板读取、进程管理、系统信息收集。

## 数据管理

### 数据导出

你可以随时导出全部数据：
- JSON 格式：完整结构化数据（会话、消息、记忆、人格画像）
- Markdown 格式：人类可读格式

### 数据删除

| 操作 | 范围 | 方法 |
|------|------|------|
| 删除会话 | 单个会话、关联消息与该会话的 L1 摘要 | CLI 执行 `ramaria session delete <ID>`（删除前需确认，外键级联删除）；桌面界面不提供删除会话的入口 |
| 删除人格 | 指定人格定义及其关联数据 | 界面与 CLI 均不提供单独删除人格的操作：人格以 `personas/` 目录下的 TOML 文件为权威来源，删除对应文件后重建数据库即可移除，关联记忆随重建一并清除；人格详情页仅支持修改名称、头像与描述，CLI `persona` 仅支持 `show`/`reload` |
| 删除导入数据 | 指定导入批次的消息 | 导入数据按会话组织，通过 CLI `ramaria session delete <ID>` 删除对应会话 |
| 删除全部记忆 | 所有 L0/L1/L2/L3 | 删除 `assistant.db` 文件后重启 |

### 非收集声明

Ramaria **不收集、不上传**以下信息：
- 使用统计数据
- 崩溃报告（本地保存，不自动上传）
- 用户行为分析
- 设备信息

崩溃日志保存在本地，用户可手动通过诊断导出功能打包发送给开发者用于问题诊断。
