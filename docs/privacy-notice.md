# Ramaria 隐私说明

> 版本：3.0
> 最后更新：2026-10-27

Ramaria 是一个**本地优先**的个人 AI 陪伴记忆系统。本说明按 3.0 的实际行为，解释数据存在哪里、什么时候会离开本机、如何控制以及如何删除。

---

## 1. 数据存储位置

默认数据目录为 `%APPDATA%\Ramaria\data\`，可用环境变量 `RAMARIA_DATA_DIR` 覆盖。

```
%APPDATA%\Ramaria\data\
├── ramaria.db                # SQLite：会话 / 消息 / 分层记忆 / 画像 / 知识 / 向量 / 设置
├── config.toml               # 非敏感配置
├── logs\ramaria.log          # 运行日志（每次启动覆盖旧文件）
├── image_cache\              # 会话浏览用的图片缓存（可清理）
├── stickers\                 # 表情资产文件（仅 CLI 主动添加时存在）
├── outgoing\                 # 本地发图目录（默认；可在设置中改指一个自定义目录）
└── personas\                 # 预留目录；3.0 的人格定义随安装包 resources/config/personas 分发
```

| 数据 | 位置 / 说明 |
|---|---|
| 会话与消息（L0） | `ramaria.db`；永久保留，不自动清理 |
| L1 摘要 / L2 事件 / L3 画像 / 知识事实 | `ramaria.db`；层间通过外键关联 |
| 文档向量 | `ramaria.db` 的 `memory_vectors`（L1 / L2 / utt）；不单独落文件 |
| 人格记录与编辑结果 | `ramaria.db`；人格定义文件随安装包分发，导入 / 导出的预设写到用户选择的位置 |
| 会话图片元数据与描述 | `ramaria.db`；图片字节按需缓存到 `image_cache\` |
| 社交绑定 / 已读水位 / 主动开关 / 设置 | `ramaria.db` |
| API Key / 平台凭据 | Windows 凭据管理器；不写入配置文件或数据库 |
| 对话框路径授权票据 | 仅进程内有效、不落盘；重启后需重新经对话框选择 |
| 通知应用标识 | `HKCU\Software\Classes\AppUserModelId\com.ramaria.app`，仅写显示名，卸载时移除 |

补充说明：

- `image_cache\` 用于导入、社交与本地发图的浏览显示；可在「设置 → 数据与系统 → 数据管理」清理，不影响原图与记忆。
- `stickers\` 只在用 `ramaria sticker` 添加资产时存在；资产行在 `ramaria.db`。
- `outgoing\` 是本地发图的默认来源目录；`send_local_image` 只接受该目录（或用户设置的自定义目录）内的文件。
- 使用嵌入模型下载命令时，模型文件会放到 `%APPDATA%\Ramaria\models\`；3.0 界面没有下载触发入口，通常由用户自备模型文件。

## 2. 什么时候会离开本机

| 场景 | 流向 | 是否可避免 |
|---|---|---|
| 本地模型（LM Studio）对话 / 记忆加工 | 只到本机 `localhost` 的 LM Studio | 不需要避免，数据不出本机 |
| 线上模型（DeepSeek / OpenAI）对话 | 当前对话 + System Prompt + 召回到的记忆 + 相关人格画像 → 所选服务商 | 切换到 LM Studio，或不使用线上后端 |
| 线上模型的结构化记忆任务 | L1 摘要的会话文本、L2 事件提取的摘要、L3 推断的事件摘要、知识抽取与风格统计文本 → 所选服务商 | 同上 |
| 图片理解 | 开启「模型支持图片理解」且使用线上模型时，图片字节 → 所选服务商 | 关闭图片理解，或使用本地模型 |
| 人格预设的 AI 拆解 | 预设中的自由文本块 → 当前后端；结构化字段直写本地 | 导入时选择「不拆解」（CLI `--no-ai`） |
| QQ 聊天记录导入 | 文件从本地读取；消息与附件元数据写本地；图片理解按上一行规则外发 | 不使用图片理解 / 使用本地模型 |
| 社交平台（QQ / Telegram） | 消息经平台 API 收发；模型生成沿用当前后端；平台侧自然可见 | 关闭通道，或只在本地对话 |
| MCP 接入 | 被检索到的记忆 / 人格随客户端对话发送给该客户端所用模型；`chat_send` / `chat_ingest` 可写回本地 | 关闭 MCP 总开关或收紧白名单 |
| 主动对话 | 与普通对话同一条生成链路；线上时相关消息与记忆摘要外发 | 关闭主动对话，或使用本地模型 |
| 检查更新 | 仅手动点击时 GET GitHub Releases API；发送 IP / User-Agent，不发送本地数据 | 不点击即可 |
| 嵌入模型下载 | 使用下载命令时访问 HuggingFace；3.0 界面无入口 | 自备模型文件即可 |

Ramaria **不包含遥测**：不收集使用统计、不自动上传崩溃报告、不做行为分析、不采集设备信息。

## 3. 对话与记忆外发

### 3.1 线上模型

选择 DeepSeek / OpenAI 时，每次生成会发送：

- 当前对话与必要的 System Prompt；
- 当前人格的画像、事实与行为规则摘要；
- 召回到的 L1 / L2 / 知识 / 原文块（受人格共享级别与召回参数约束）。

**3.0 起，本地记忆恒随对话注入，不再提供“关闭线上记忆注入”的开关。** 如果希望记忆不离开本机，请使用 LM Studio 本地后端。

首次使用线上后端前，必须完成显式隐私确认；确认按「provider + Base URL」粒度记录，切换 provider 或修改地址后需要重新确认。LM Studio 本地模式不会出现该确认。

### 3.2 结构化记忆任务

记忆不是只在你发消息时才加工。以下任务也会调用当前后端：

- 会话结束后的 L1 摘要；
- L1 累积后的 L2 事件提取；
- L2 累积后的 L3 人格推断、漂移检测与重载；
- 知识事实抽取、行为规则学习、表达风格统计；
- 导入后处理与「继续处理」中的摘要补跑。

使用线上模型时，这些任务会把对应的会话文本或摘要发送到服务商；结构化任务始终关闭思考模式，不产生 `reasoning_content`。

### 3.3 思考内容

DeepSeek 对话路径默认开启思考模式，**思考在模型服务端完成**。模型返回的 `reasoning_content` 不写入数据库、不进入日志、不展示在界面，仅用于空回复诊断（长度计数）。关闭方式：「设置 → 模型与检索 → 后端配置 → 思考模式」。

## 4. 图片理解

3.0 的图片理解用于导入、社交与本地发图，生成一段简短描述供摘要与展示；**对话生成不会把当轮图片作为多模态输入**。

| 方面 | 说明 |
|---|---|
| 触发条件 | 「设置 → 模型与检索 → 嵌入与图片理解 → 当前模型支持图片理解」显式开启；默认关闭 |
| 线上外发 | 使用线上模型且已完成隐私确认时，图片以 base64 内联随理解请求发送到服务商 |
| 本地模式 | LM Studio 模式下图片只发往本机 |
| 本地发图 | 桌面发送本地图片后，后台异步生成描述；不阻塞消息发送 |
| 存储 | 原图按需写入 `image_cache\`；描述写入 `ramaria.db` 的附件记录 |
| 隐私门禁 | 线上后端未完成隐私确认时，理解不执行，附件保持「待处理」 |
| 失败降级 | 理解失败或模型不支持时，图片以占位符保留，不阻塞导入与对话 |

如果图片包含不希望外发的内容，请保持图片理解关闭，或切换到 LM Studio 本地模式。

## 5. 人格预设导入与导出

- 预设文件经原生文件对话框选择（选择即授权，票据仅本次会话有效）；文件形态、存在性与符号链接校验不变。
- 结构化字段（traits / facts / examples / behavior_rules / prompt）直写本地数据库，不经模型。
- 含自由文本块时，可选择 AI 拆解；拆解会把原文发送到当前后端。线上后端沿用 `provider + Base URL` 隐私确认，未确认时自动跳过拆解，原文保留在人格配置里，导入照常完成。
- 导出人格画像只含人格本身内容，**默认不含对话示例**；开启「含对话示例」会包含真实对话片段，导出文件写到用户选择的位置。
- 角色卡可能包含作者的原创设定文本；导入仅供本地使用，请遵守来源作者的授权范围。

## 6. QQ 聊天记录导入

| 方面 | 说明 |
|---|---|
| 文件读取 | 从本地选择 JSON 文件；解析与去重都在本机完成 |
| 存储 | 消息、会话、参与者人格、附件元数据写入本地 `ramaria.db` |
| 去重 | 同一文件内去重；跨文件按导入指纹（SHA-256 前 16 位 hex）跳过已导入消息 |
| 图片 | 启用图片理解时按 §4 处理；未启用或失败时保持「待处理」，可「继续处理」 |
| 画像 | 为聊天参与者创建 `source="qq"` 人格；可在人格页查看与编辑 |
| 外发 | 导入本身不上传；仅图片理解与后续对话 / 记忆加工按当前后端规则外发 |

导入的历史记录与本地对话同等对待；删除对应会话即可删除该批消息与 L1。

## 7. 社交平台接入

开启「设置 → 社交与接入 → 社交平台接入」后，Ramaria 可通过 QQ（OneBot v11 / NapCat 等协议端）或 Telegram（Bot API）收发消息。

| 方面 | 说明 |
|---|---|
| 接收 | 消息与图片来自平台侧；Telegram 经长轮询拉取，QQ 经 WebSocket 推送；内容写入本地 SQLite |
| 图片 | 下载到本地（≤ 20 MB）并可做一次理解；理解 / 下载成功的图片写入 `image_cache\`，会话中可看到原图 |
| 撤回 | QQ 撤回事件用于本地标记 `recalled_at` 与调整上下文；Telegram Bot API 不提供撤回事件 |
| 表情 | 表情资产由你本地添加；仅命中时经平台 API 发到对应会话；匹配在本地完成，表情图片与描述不上传模型 |
| 平台外发 | 回复与你开启的主动消息经平台 API 发回对应会话；平台侧自然可见 |
| 模型外发 | 回复生成与图片理解沿用当前后端；线上时相关消息与记忆上下文会发送到服务商（3.0 起恒注入，无关闭开关） |
| 群聊 | 只处理被 @ 与被回复的消息；内容按发言人归属入库并参与记忆管线 |
| 凭据 | QQ access token / Telegram bot token 存在 Windows 凭据管理器，不写入配置文件、不记入日志；可在设置页清除 |
| 第三方依赖 | QQ 接入依赖第三方协议端；其运行、登录与风控风险由你自行评估，Ramaria 不与之共享数据 |

> 社交平台上的原始消息始终由平台方持有；本系统的“不出本地”仅指自身不上传，不代表平台侧不持有这些数据。

## 8. MCP 接入

在桌面「设置 → 社交与接入 → MCP 接入」开启总开关后，外部 MCP 客户端可通过 stdio 使用 Ramaria 的记忆与人格。

| 方面 | 说明 |
|---|---|
| 被检索到的记忆 | 随客户端对话发送给该客户端所用模型；`memory_recall` / `chat_send` 均可能包含 |
| 外部对话回流 | `chat_send` / `chat_ingest` 写入本机数据库，与本地对话同等对待 |
| 原文块（utt） | 默认不出端；`[mcp].allow_raw_text = false` 时返回中不含原文 |
| 控制项 | 总开关（默认关闭）、人格白名单、原文开关、写入与封存开关、召回条数与文本预算 |
| 进程 | MCP 服务由客户端按需拉起，桌面端不常驻；stdout 只承载协议消息 |
| CLI | 安装包不随带 `ramaria` 命令行；没有 CLI 时客户端无法启动 MCP 服务 |

> 挂载 MCP 后，被检索到的记忆与回流内容会随对话发送给该客户端所使用的模型；请只挂载你信任的客户端。

## 9. 主动对话

主动对话仅随桌面应用装配；CLI 与 MCP 不会主动发言。

| 数据类型 | 流向 | 说明 |
|---|---|---|
| 主动生成请求 | 本地 SQLite +（线上后端时）服务商 | 与普通对话同一条生成链路；受隐私确认约束 |
| 主动消息本身 | 本地 SQLite | 与用户消息同权参与后续记忆加工，不额外外传 |
| 选题与判据信号 | 仅本地 | 事件 / 规则摘要与活跃时段信号在本地组装；判据调用只含摘要，不含原文 |

控制项：

- **总开关**：设置 → 主动对话；关闭即完全停用。
- **逐人格三态**：自动 / 开启 / 关闭（主动消息名单）；默认聊过一次后自动开启。
- **打扰控制**：每日上限、全局日上限、免打扰时段、最小空闲、投递冷却、连续未回应退避、首次启用宽限。
- **隐私门禁**：线上后端未完成隐私确认时，主动对话静默跳过。
- **只读基线**：`ramaria probe baseline` 仅读取本地记录，不联网、不回写。

## 10. 检查更新与模型下载

### 10.1 检查更新

「关于浮层 → 检查更新」是**手动操作**，不会在后台自动检查。点击后 GET `https://api.github.com/repos/entergirl/Ramaria-s/releases/latest`，发送 IP 与 `User-Agent`，不发送本地数据、记忆或凭据。失败时只显示错误，不影响使用。

### 10.2 嵌入模型下载

`download_embedding_model` 命令具备从 HuggingFace 下载预置模型的能力；3.0 界面没有触发入口，通常由用户自备模型文件。若通过命令触发，会访问 `https://huggingface.co` 下载模型文件，不上传本地数据。

## 11. API Key 与日志

### 11.1 API Key / 平台凭据

- 存储在 **Windows 凭据管理器**，不写入 `config.toml`、不写入数据库、不进入日志。
- 通过 HTTPS 发送到所选 API 服务商；平台 token 通过对应平台 API 使用。
- 界面与 CLI 遮蔽显示为「前 3 字符 + `****` + 后 3 字符」；长度 ≤ 4 时整体 `****`。
- 诊断导出时配置中的 Key 替换为 `[REDACTED]`。

### 11.2 日志策略

- 日志文件：`%APPDATA%\Ramaria\data\logs\ramaria.log`；每次启动覆盖旧文件。
- **不记录**：完整用户消息、完整记忆内容、完整 Prompt、LLM 原始响应、API Key。
- **记录**：tracing span、请求 ID、耗时、错误链、长度与计数等元数据。
- 导入路径中的个人标识（QQ 号、昵称、文件路径）经遮蔽后才进入日志。
- `[logging].log_full_prompt` 为**预留配置项（当前实现未接线）**：无论取值如何，3.0 都不会记录完整 Prompt。

## 12. 前端安全

桌面应用使用 WebView 渲染界面，采取以下措施：

### 12.1 内容安全策略（CSP）

```
default-src 'self';
style-src 'self';
script-src 'self';
connect-src 'self' ipc: http://ipc.localhost https://ipc.localhost https://api.deepseek.com https://api.openai.com;
img-src 'self' data: blob:;
font-src 'self'
```

- 禁止内联脚本与内联样式。
- 禁止加载远程脚本与远程图片；`blob:` 仅用于本地附件图片。
- 字体自托管，不依赖外部 CDN。
- 网络连接仅允许 Tauri IPC 与已配置的 API 端点。

### 12.2 消息渲染

对话正文按纯文本渲染，不做 Markdown 解析、不插入原始 HTML：

- 保留换行；`||` 只作为分条气泡的展示分隔符，不改变落库内容。
- 所有文本经 `textContent` / Vue 插值渲染，无 `innerHTML` 路径。
- 错误消息同样以纯文本呈现，防止 XSS 注入。

### 12.3 Tauri 权限

| 权限 | 用途 |
|---|---|
| `dialog` | 保存 / 打开文件与选择目录 |
| `notification` | Windows Toast 桌面通知 |
| `store` | 非敏感偏好本地存储（主题 / 导航位置 / 调试开关） |
| `core:window` | 窗口显示 / 隐藏 / 关闭 |

不具备的权限：网络文件系统访问、剪贴板读取、进程管理、系统信息收集。

## 13. 数据管理

### 13.1 导出范围

设置页与 CLI 的导出是**会话导出**，不是全库备份：

- JSON：带版本信封的会话与消息；按人格导出时附加该人格的未吸收 L1 摘要。
- Markdown：人类可读的会话记录。
- **不包含** L2/L3、知识事实、人格定义、向量、设置与社交绑定。

需要完整备份时，请复制 `%APPDATA%\Ramaria\data\`（至少 `ramaria.db`；需要图片与表情时连同 `image_cache\`、`stickers\`、`outgoing\` 一并复制）。

### 13.2 删除

| 操作 | 范围 | 方法 |
|---|---|---|
| 删除会话 | 单个会话、关联消息与该会话的 L1 | CLI `ramaria session delete <ID>`；桌面不提供删除会话入口 |
| 删除导入数据 | 指定导入批次的会话 | 同上，按会话删除 |
| 删除人格 | 人格记录及其关联记忆 | 界面与 CLI 均不提供单独删除人格；删除 `ramaria.db` 会清空库内人格。人格定义文件随安装包分发，删除数据库后下次配置 / 重载会重新注册 |
| 删除全部记忆 | 所有 L0/L1/L2/L3、知识、向量、设置、绑定 | 关闭应用后删除 `ramaria.db`，重启重新配置 |
| 清理图片缓存 | `image_cache\` 内的图片缓存 | 设置 → 数据与系统 → 数据管理 → 清理图片缓存 |
| 删除表情资产 | `stickers\` 与资产行 | CLI `ramaria sticker remove <id>` |
| 删除日志 | `logs\ramaria.log` | 手动删除；下次启动重新创建 |

2.x 的 `assistant.db` 不被 3.0 读取，也不会被自动删除；需要清理时请自行备份后删除。

### 13.3 非收集声明

Ramaria **不收集、不上传**以下信息：

- 使用统计数据；
- 崩溃报告（不自动上传；如本地日志含错误信息，可手动经诊断导出）；
- 用户行为分析；
- 设备信息。

诊断包在本地生成，由你决定是否发送给开发者。

## 14. 离线使用

- 使用 LM Studio 后端与本地嵌入模型时，Ramaria 可完全离线运行。
- 无需注册账号、无需联网。
- 自托管字体确保界面在离线环境下完整显示。
- 社交接入、MCP、检查更新与模型下载属于需要网络的功能，不使用时可保持关闭。
